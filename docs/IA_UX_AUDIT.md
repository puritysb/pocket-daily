# IA·UX 재검토

검토일: 2026-10-05. 기준은 [제품 IA](PRODUCT_IA.md), 확인 대상은 현재 소스와 실행 중인 Mac 앱이다. 화면 이동과 펼치기, 기존 카드 선택만으로 과업의 경계를 검토했다. 새 연결·전송·설정 적용은 실행하지 않았다. 사용자 대상 사용성 실험 결과가 아니라, 원래 IA와 구현을 대조한 검토다.

## 2026-10-05 판정

Library와 My Reader의 상위 분류, 선택한 책의 전송 작업, 독립적인 앱 독서는 구현됐다. 그러나 사용자에게 보이는 편집 대상·적용 범위·내용의 소속이 일관되지 않는다. **기능 통합과 로컬 회귀 검증을 마쳤다고 전체 IA·UX가 완료된 것으로 판정한 것은 잘못이다.**

원래 IA는 정보의 소속을 정의했고 모든 항목을 메뉴로 노출하라는 뜻이 아니었다. 구현 설계에서 기존 편집기·전송 경로를 재사용하면서 각자의 적용 버튼과 준비 상태까지 사용자 화면에 남겼다. 설계와 통합 검토가 이 타협을 걸러내지 못했다.

## 2026-10-05에 확인한 문제

### 1. 홈을 꾸미는 한 과업에 적용 범위가 세 개다 — 우선 수정

- 원칙: 편집 화면에 미리보기·조정·상태·하나의 적용 행동을 제공한다. [원래 IA의 편집 규칙](PRODUCT_IA.md#화면-꾸미기와-읽기-방식).
- 현재: 상단 `Apply to Reader`는 현재 화면 구성만 보낸다. 같은 화면 안에 `Apply cards to Reader`, `Apply content to Reader`가 별도로 있다. 마지막의 content는 카드까지 포함하지 않고 날씨·일정만 보낸다.
- 사용자 영향: 홈에 표시할 카드와 지역을 수정한 뒤 무엇을 몇 번 적용해야 하는지 내부 데이터 분류를 알아야 한다. `Shared sources · layout changes apply separately`라는 설명은 이 구조적 혼란을 사용자에게 해석시키고 있다.
- 근거: [상단 적용](../Sources/Studio/ProfileStudioView.swift), 같은 파일의 `applyControls`, `cardsEditor`, `sharedContentControls`.
- 수정 기준: 하나의 활성 편집 작업에는 하나의 적용 범위와 주 행동만 존재한다. 내부 전송이 여러 단계여도 UI에 여러 Apply를 늘어놓지 않는다. 여러 단계를 묶는다면 부분 실패를 정확히 표시하며 원자적 적용이라고 주장하지 않는다.

### 2. 선택한 대상과 미리보기가 달라진다 — 우선 수정

- 재현: Screens → Home → My cards 펼치기 → 기존 카드 선택.
- 현재: Home 선택과 상단 Home 작업 범위를 유지한 채 미리보기는 `Card page`로 바뀐다. 홈 구성 컨트롤도 함께 남는다. 실행 중인 Mac에서 확인했다.
- 사용자 영향: 지금 홈을 고치는지 카드 원본을 고치는지, 상단 행동이 미리보기에 보이는 내용을 보내는지 판단하기 어렵다.
- 근거: [ProfileStudioView](../Sources/Studio/ProfileStudioView.swift)의 `cardsEditor`는 `preview = .card`로 바꾸지만 상단 적용은 `screen`을 기준으로 한다.
- 수정 기준: 제목·선택 대상·미리보기·변경 상태·주 행동이 같은 작업을 가리킨다. 공통 원본 편집은 명확한 별도 작업으로 진입하고, 사용 중인 화면을 알려 준 뒤 원래 화면으로 복귀한다. Home/Sleep에는 사용할 내용과 배치만 둔다. 공통 원본을 새 최상위 메뉴로 늘릴 필요는 없다.

### 3. 같은 책 보내기가 새 작업과 기존 파일 준비로 나뉜다 — 우선 수정

- 원칙: 서재에서 책을 선택해 보내며, macOS의 SD 카드 복사도 보내기 흐름의 대상이다.
- 현재: 서재의 `Send to Reader`는 새 책 작업 시트를 연다. On Reader에는 `Choose from Library` 외에 `Add files and previous prepared items`가 남고, 여기서 파일 선택·글 작성·SD 복사를 제공한다. 준비한 파일과 심볼 폰트 안내도 기기 보관함 안에 섞인다.
- 사용자 영향: 파일을 앱에 보관할지 기기로만 보낼지 진입점에 따라 달라진다. 서재의 책을 SD 카드로 보내려면 다른 메뉴에서 파일을 다시 찾아야 한다. `previous prepared items`는 사용자 목적보다 이행 중인 구현 상태를 드러낸다.
- 근거: [ContentView](../Sources/ContentView.swift)의 `filesContents`, `FilesInspector.addMenu`, `PreparedTransferQueue`; [BookTransferSheet](../Sources/Library/BookTransferSheet.swift).
- 추가 혼재: 연결된 기기의 저장 공간 패널은 SD 용량보다 RAM 여유량과 펌웨어의 메모리 보고 방식을 먼저 보여 준다. 책을 더 넣을 수 있는 저장 공간과 작업 메모리는 다른 정보다. [ReaderStoragePanel](../Sources/ReaderStorage.swift)의 RAM 정보는 Device의 진단에 속해야 한다.
- 수정 기준: 선택한 콘텐츠와 대상이 전송 완료까지 유지된다. 무선과 SD는 동일한 보내기 흐름에서 선택하되 결과 의미는 구분한다. 기존 준비 항목은 필요한 경우에만 작업 복구로 노출한다. 앱에서 읽지 못하는 기기 전용 파일은 지원 범위에 맞는 별도 고급 가져오기로 유지할 수 있지만 일반 책 흐름을 복제하지 않는다.

### 4. 연결과 복구가 모든 상태에서 현재 과업으로 이어지지 않는다 — 우선 수정

- 소스에서 확인: 책 저장 결과가 불확실하고 다른 리더가 연결된 경우, `needsConfirmation` 분기는 결과 확인 버튼을 비활성화하고 원래 리더에 재연결하라는 문장만 표시한다. 작업 시트 안의 연결 진입 버튼은 이 분기에 없다. 뒤쪽의 다른 대상 처리 분기에는 연결 버튼이 있지만 먼저 실행되는 결과 확인 분기에는 도달하지 않는다.
- 소스에서 확인: 다른 작업을 기다릴 때 `View reader task`는 실제 작업을 열지 않고 항상 Device로 이동한다. 공통 작업 표시도 일반 작업을 Device로 보낸다. On Reader에서 파일을 가져오는 작업 등은 진행·취소가 있는 화면과 목적지가 달라진다.
- 연결 안내에는 같은 Wi-Fi, 직접 연결, Bluetooth와 파일 전송 관계 설명이 한꺼번에 나온다. 작업 내 연결 진입은 개선됐지만, 과업별로 다음 행동 하나를 안내하는 수준에는 못 미친다.
- 근거: [BookTransferSheet](../Sources/Library/BookTransferSheet.swift)의 `actions`; [ContentView](../Sources/ContentView.swift)의 `onDevice`, `auxiliaryTask`, `ConnectionInspector.actions`.
- 수정 기준: 결과 미확인·다른 리더 연결·다른 작업 대기에서도 현재 작업을 유지하고 필요한 연결 또는 실제 진행 중인 작업으로 이동한다. 다른 연결 방법은 필요할 때 펼치며, 직접 Wi-Fi 전환의 영향은 선택 전에 명시한다.
- 중복과 구별할 점: Settings의 Bluetooth 바로가기와 Device의 Continue Reading 바로가기는 각 소유 화면을 가리키므로 실제 설정 소유권 중복으로 판정하지 않는다. 공유 정책은 Settings, 리더 신원·페어링은 Device가 소유하는 원칙을 유지한다.

### 5. 개요가 상태 중심 화면보다 메뉴의 두 번째 목록에 가깝다

- 현재: Mac 사이드바에 있는 On Reader·Screens·Reading·Device를 Overview에서 큰 카드 네 개로 반복한다.
- 판단: 바로가기의 반복 자체는 결함이 아니다. 그러나 넓은 화면에서는 새 정보가 적고 이미 보이는 목적지를 다시 고르게 한다. 작은 화면에서는 이 목록이 탐색 역할을 할 수 있으므로 플랫폼에 맞게 다뤄야 한다.
- 근거: [ContentView](../Sources/ContentView.swift)의 `readerOverview`.
- 수정 기준: Mac 개요의 중심은 현재 리더, 연결 상태, 진행·복구할 작업과 필요한 다음 행동이다. 하위 메뉴 목록이 주 콘텐츠가 되지 않는다. 모바일에서도 상태 요약과 목적지 탐색의 역할을 구별한다.

### 6. Reading에서 정확한 정보가 과도한 설명으로 표현된다

- 현재: 페이지 버튼 설정에 위치 설명, Standard 메뉴, 이전/다음 대응표, 위치 안내 문장, 기기 그림, 범례, 회전 설명, 전면 버튼 수 설명이 누적된다. Mac 최초 화면에서도 그림 일부는 아래로 밀린다.
- 판단: X3/X4를 구분하는 데이터와 그림을 갖춘 것은 유효하다. 그러나 설명을 더하는 방식으로 해결해 사용자가 실제 누를 버튼과 결과를 빠르게 파악하기 어렵다.
- 근거: [ProfileStudioView](../Sources/Studio/ProfileStudioView.swift)의 `readerSettings`; [ReaderButtonDiagram](../Sources/Studio/ReaderButtonDiagram.swift).
- 수정 기준: 선택한 방향의 기기 그림에서 버튼 위치와 이전/다음 결과를 바로 보여 준다. 중복 대응표·안내 문장은 줄이고, 상세 제약은 필요할 때 연다. 읽기 미리보기와 버튼 그림의 역할도 시각적으로 구별한다.

## 유지할 기반과 다시 설계할 부분

유지할 것은 독서 엔진, 서재 저장, 위치 교환 계약, 전송 작업과 복구, 초안 저장, 기기 기능 확인과 펌웨어 검증이다. Library/My Reader의 역할 분리와 선택한 책을 잃지 않는 작업 시트도 유지할 수 있다.

다시 설계할 것은 편집 작업의 경계, 공통 원본의 진입과 복귀, 통합된 보내기 대상 선택, 상태 중심의 리더 개요와 연결 안내다. 구현 모듈별로 화면을 나누지 말고 다음 시나리오가 끝나는 단위로 설계·검토한다.

| 시나리오 | 수용 기준 |
| --- | --- |
| 연결 없이 홈을 꾸미고 적용 | 한 대상·한 미리보기·한 적용 범위. 연결 후 같은 초안으로 복귀 |
| 홈에서 쓰는 카드 원본 수정 | 원본 편집임을 명시하고 Home/Sleep 영향 표시. 복귀 후 홈 미리보기 유지 |
| 서재의 책을 리더 또는 SD로 보내기 | 책을 다시 고르거나 파일 시스템에서 다시 찾지 않음. 대상에 맞는 진행·결과 |
| 다른 기기에서 이어 읽기 | 파일 전달과 위치 공유를 구별하고 필요한 연결만 작업 안에서 안내. 임의 페이지 이동 없음 |
| X3/X4의 읽기 방향과 버튼 변경 | 회전 후 실제 버튼 위치와 결과를 그림에서 확인. 앱 외관과 기기 옵션의 범위 구별 |

당시 위 기준은 충족하지 못했다. 아래는 후속 구현과 재검토 기록이다. 기존 테스트 수나 스크린샷 생성 성공만으로 수용 기준을 통과 처리하지 않는다.


## 2026-10-06 수정 및 재검토

[개선 명세](IA_UX_REFINEMENT.md)에 따라 여섯 문제를 수정했다. 최신 실행 증거와 남은 하드웨어 수용은 [구현 보고](IA_IMPLEMENTATION_REPORT.md)에 모은다. 위 항목의 ‘현재’는 최초 감사 시점의 구현을 뜻하며, 과거 문제의 근거를 보존하기 위해 남겼다.

| 최초 문제 | 후속 구현과 확인 |
| --- | --- |
| 복수 Apply | Home/Sleep은 구성 적용 하나만 제공한다. 카드·날씨/일정은 각각 별도 원본 작업으로 열고 주 행동을 하나로 제한했다. |
| 부모 대상과 미리보기 불일치 | 원본 편집기를 닫으면 Home/Sleep 선택과 미리보기를 유지한다. 연결 화면을 편집기 안에서 열어 확정 전 지역 입력도 보존한다. Mac에서 직접 확인했다. |
| 일반 책 경로 중복 | 추가·작성은 Library로 통합했다. On Reader는 기기 파일·SD 공간과 기기 전용 파일 보조 동선만 소유한다. 선택한 책 보내기에서 Wi-Fi/SD를 선택하며 결과는 분리한다. |
| 복구의 막다른 길 | 다른 리더가 연결된 결과 미확인 작업에서도 원래 리더에 재연결할 수 있다. 진행 중 작업은 실제 소유 화면과 Home/Sleep 범위로 돌아간다. |
| Mac 개요의 메뉴 반복 | 네 목적지 카드 대신 현재 리더·상태·작업·복구를 보여 준다. 모바일의 목적지 탐색은 유지한다. |
| Reading 설명 누적 | 실제 버튼 그림의 Previous/Next로 통합하고 중복 대응표를 제거했다. 모델·방향별 그림은 유지한다. |

교차 검토에서 발견한 원본 작업 재진입 잔류, Sleep 대상 오인, 연결 후 임시 입력 소실과 복수 전송의 제어 범위 유실도 함께 수정했다. 이번 결론은 과업 소유권과 동선의 일관성에 대한 코드·실앱 검토다. 사용자 대상 사용성 실험이나 물리 리더의 연결·전송 완료를 대신하지 않는다.
