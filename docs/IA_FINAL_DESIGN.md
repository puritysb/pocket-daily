# Pocket Daily IA 구현 설계

작성일: 2026-10-05, 내비게이션 개정: 2026-10-09. 상태: UX 재검토를 반영한 구현 기준. 구현 및 검증 결과는 [구현 보고](IA_IMPLEMENTATION_REPORT.md)에 기록한다.

사용자 요청에 따라 [제품 IA](PRODUCT_IA.md), [화면 명세](PRODUCT_UX_SPEC.md), [전환 계획](IA_MIGRATION_PLAN.md)를 구체화한다. 2026-10-05 [재검토](IA_UX_AUDIT.md)에서 복수 Apply와 전송 동선 분리 등 불일치를 확인했고, 아래 설계를 [개선 구현 기준](IA_UX_REFINEMENT.md)에 맞춰 수정했다. 설계 문서의 갱신은 구현 완료나 사용성 수용을 뜻하지 않는다. 계정, 전체 파일 자동 양방향 동기화, 여러 리더 동시 관리, 책별 앱 외관 예외, 기기 라이브 화면 캡처는 범위 밖이다.

## 내비게이션과 첫 화면

첫 화면은 Library다. 최상위 목적지는 Library와 My Reader 두 개다. Library 안의 Books와 Articles는 읽을 콘텐츠의 분류이고, 책을 열면 같은 창에서 읽는다. 기존 글 저장·구독·직접 작성·가져오기 기능의 진입점을 보존한다. 책 제목과 저자 등 이미 가진 정보로 찾는 로컬 검색을 제공한다.

My Reader의 첫 화면은 기기 상태, 저장된 편집과 전송 작업, 기기 보관함을 함께 보여 준다. Overview와 On Reader를 통합하고, Screens·Reading·Device를 주 내비게이션에서 제거한다.

- Reader settings: 기기 카드에서 연다. Home screen / Sleep screen / Reading preferences를 편집 영역 안의 메뉴로 선택한다. 미연결에도 편집하며 적용 단계에서 연결한다.
- Manage reader: 기기 카드의 Reader options 메뉴에서 연다. 연결·Bluetooth 등록·업데이트·문제 해결을 제공한다.
- Library에서 책을 여는 독서와 Reader settings의 Reading preferences는 이름과 소속으로 구분한다.

휴대폰은 Library / My Reader 탭과 상세 화면의 뒤로 가기를 사용한다. 넓은 화면도 사이드바의 My Reader 한 항목과 상세 화면의 뒤로 가기를 사용한다. 연결 전후에 메뉴가 사라지거나 순서가 바뀌지 않는다.

Settings는 보조 진입점이며 현재 창에 붙은 시트로 열린다. macOS 단축키도 같은 창의 시트를 연다. 앱 읽기 종료 시 서재의 분류·검색·선택·스크롤을 유지한다. 기기 연결을 위해 새 창을 만들거나 다른 Space로 이동하지 않는다.

## 기기 상태와 행동

| 상태 | 요약 | 가능한 행동 |
| --- | --- | --- |
| 등록 이력 없음 | 연결한 리더 없음 | Connect reader, Reader settings 예시 편집 |
| 기억한 기기만 있음 | 기기 이름과 마지막 확인 정보 | Connect, 저장된 편집, 마지막 보관함 확인 |
| Bluetooth 위치 교환 지원 | 위치 공유 상태와 마지막 완료 시점 | 위치 공유 관리. 파일 전송은 필요한 Wi-Fi 연결 안내 |
| Wi-Fi 연결 | 확인된 모델과 사용할 수 있는 기능 | 보관함·지원 설정·파일 전송 |
| 다른 작업 진행 중 | 작업명과 단계 | 같은 작업 열기. 경쟁하는 기기 작업은 대기 이유 표시 |
| 오류 또는 결과 불확실 | 필요한 행동 한 가지와 원인 | 재연결, 결과 확인, 남은 항목 재시도 등 해당 복구 |

상태는 기존 기기 정보에서 계산하며 UI만의 독립적인 연결 상태를 만들지 않는다. 기억한 주소나 모델명은 기기 신원의 증명이 아니다. 같은 기기인지 확인할 수 없는 연결은 그 한계를 유지한다. 기기 미연결 상태에서 배터리나 파일 목록을 현재 값으로 표시하지 않는다.

개요에는 관련 없는 설정 토글과 상세 프로토콜 설명을 늘어놓지 않는다. Mac에서는 사이드바의 네 목적지를 큰 카드로 반복하지 않고 현재 리더와 필요한 다음 행동을 보여 준다. 모바일은 간결한 목적지 목록을 제공한다. 진행 중 또는 확인이 필요한 작업이 있을 때 공통 작업 진입점을 강조한다. 완료를 확인한 작업은 사용자가 닫으면 방해하지 않고, 미확인 결과는 해결할 때까지 다시 찾을 수 있어야 한다.

## 기기 보관함과 서재

My Reader의 보관함은 선택한 기기에 실제로 관측된 파일을 보여 준다. 전송 큐가 파일 목록의 자리를 대신하지 않는다. 목록에는 이름, 필요한 크기 정보, 앱에도 있는지, 관측 시점을 표시한다. 앱과 매칭되는 파일은 해당 책 열기로 이어지고, 기기에만 있는 지원 EPUB는 Add to Library로 이어진다.

기기의 파일 다운로드 지원이 없으면 그 이유를 짧게 알리고 버튼을 사용할 수 없게 한다. TXT·Markdown을 EPUB와 동일하게 다운로드 후 바이트 일치한다고 주장하지 않는다. 파일명과 크기로 추정한 매칭과 지문으로 확인한 동일 콘텐츠를 구별할 수 있게 한다.

기기에서 삭제는 대상 파일과 리더를 명시하며 앱 서재 사본을 지우지 않는다. 일반 책 추가·작성은 Library가 소유하고 기기 보관함은 이 흐름으로 연결한다. 기기 전용 파일은 보조 가져오기에서 다룬다. RAM과 폰트 설치는 Manage reader의 관련 상세로 옮기고 보관함에는 SD 저장 공간을 둔다. Mac의 SD 복사는 선택한 책 보내기 시트에서 폴더만 선택한다. 원본 바이트를 보존하며 완료는 SD 복사로 표현하고 무선 전송 완료나 기기 설치 완료와 구별한다.

## 책 보내기의 확정된 인터페이스

책의 Send to Reader…는 현재 창의 작업 시트를 연다. 시트가 열린 것만으로 업로드하지 않는다. 대상, 책 목록, 단계, 주 행동을 유지한 채 필요한 연결 과정을 같은 시트에서 진행한다. 연결 후 Send N Books를 명시적으로 누르면 선택한 항목만 실행한다.

작업 계층은 기존 PocketModel에 연결된 다음 책임을 제공한다. 실제 명칭이 조정되면 구현 계획의 대응표도 갱신한다.

- `bookTransferJobs`와 ID 조회: 앱이 소유한 작업 및 책별 결과.
- `createBookTransferJob`: 명시적인 LibraryBook 목록을 정확한 준비 파일 ID에 연결. 활성 동일 작업은 재사용.
- `selectBookTransferTarget`: 아직 지정하지 않은 대상 선택. 이미 지정한 대상과 다르면 자동 재지정 금지.
- `sendBookTransferJob`, `pauseBookTransferJob`, `checkBookTransferJob`, `retryBookTransferJob`, `discardBookTransferJob`: 각 작업의 ID 범위만 실행.
- `canSendBookTransferJob`: 지원 기능, 대상, 준비 완료, 불확실한 결과, 경쟁 작업을 판단해 보내기 가능 여부 계산.

저장은 작업 생성 및 실행 대상 고정 전에 완료한다. 준비 API는 생성한 ID를 반환한다. 게시를 시작할 때는 불확실한 완료 가능성을 먼저 기록하고, 저장이 확인되면 완료 결과를 영속화한 뒤 준비 사본을 정리한다. 어느 단계에서 종료돼도 완료로 추정하거나 중복 게시하지 않도록 기존 게시 영수증 조회를 재사용한다. 조회할 수 없으면 Check result 상태를 유지한다.

일시 중지는 전송 Task 종료와 정리를 기다리는 기존 실행권 관리에 따른다. 닫기는 취소나 삭제가 아니다. 앱이 실행 가능한 동안 작업을 이어가며, OS 중단 또는 앱 재시작 후에는 복구하되 자동 전송하지 않는다. 일부 완료된 작업의 재시도는 미완료 항목만 대상으로 한다.

새로 선택한 책과 기존 종류별 준비 큐는 섞지 않는다. 기존 준비 항목은 실제 항목이 있을 때만 보조 전송·복구 영역에 노출하며 새 작업을 Previous라고 부르지 않는다. 펌웨어는 책 작업에 포함될 수 없다. 같은 책 작업을 반복해서 열면 진행 중인 같은 작업이 열린다. SD 결과는 같은 선택 목록에 속하되 무선의 대상·게시 불확실성·완료 기록과 분리한다. 디렉터리 권한은 작업 시 사용자가 선택하며 재시작 후 자동 복사하지 않는다.

결과 미확인 상태에서 다른 리더가 연결되어도 작업 안에서 원래 대상에 재연결할 수 있다. 진행 중인 다른 작업 보기는 실제 작업 소유 화면으로 이어진다. 모든 작업을 Device로 보내지 않는다.

## Reader settings 편집

셸은 Reader settings라는 하나의 상세 경로를 연다. `ProfileStudioView`는 Home/Sleep/Reading preferences를 편집 범위로 선택하며, 그 선택은 같은 창의 셸과 공유해 화면을 나갔다 돌아와도 유지한다. 작업 복구는 해당 범위나 원본 편집기를 연다. 기기/미리보기 모델과 연결 상태는 넓은 화면과 작은 화면 모두 같은 편집기 상단에서 표시한다.

Home, Sleep, Reading에 속한 변경만 각각 Apply to Reader로 보낸다. 활성 편집 작업에는 적용 행동 하나만 둔다. 제목·선택 대상·미리보기·상태·적용 범위는 항상 일치하며 카드 선택으로 Home/Sleep 미리보기를 카드 페이지로 바꾸지 않는다. 적용 전에도 미리보기가 나오며 조정 중에는 최신 요청만 렌더링하도록 기존 취소·중복 억제를 활용한다. 수신한 기기 라이브 프레임이라고 표시하지 않는다.

| 범위 | 편집 내용 |
| --- | --- |
| Home | 표시할 페이지·Daily panel·시작 화면 등 해당 홈 구성 |
| Sleep | 대기 화면 종류·구성·표지·절전 시간·WAKE 표시 등 해당 화면 구성 |
| Reading | 글자 크기·줄 간격·여백·기기 방향·페이지 버튼 동작 |
| Shared content | 카드 원본, 날씨 지역, 일정 원본과 포함 여부 |

각 범위의 실제 wire 필드는 기존 ProfileMerge 범위와 펌웨어 계약에 맞춘다. UI가 옵션을 다른 화면에 배치한다고 다른 범위의 미적용 값을 묵시적으로 보내지 않는다. 적용 시 전송할 스냅샷을 고정하고, 전송 도중 추가 편집은 다음 변경으로 남긴다.

초안은 저장 대상 신원을 갖는다. 특정 리더에서 시작한 초안을 다른 리더에 자동 적용하거나 자동 병합하지 않는다. 기존 스키마의 신원 없는 초안은 일반 오프라인 초안으로 보존한다. 연결 시 비교한 뒤 명시적인 적용으로 채택한다. 이미 특정 기기에 묶인 초안을 다른 기기에서 사용하려면 그 선택을 명시하며 원래 초안을 보존한다. 기기별 보관은 여러 기기를 동시에 관리하는 새 UI를 요구하지 않는다.

불러오기 실패나 지원하지 않는 저장 형식을 빈 초안으로 덮어쓰지 않는다. 저장 성공만 앱에 저장됨으로 표시한다. 기기 설정 저장, 화면 표시 확인, 실제 책 표시 여부는 확인된 결과에 맞춰 구분한다.

## 기기별 읽기 옵션

X3/X4의 실제 기기별 버튼 위치와 방향별 동작은 [기기 기능 표](READER_CAPABILITIES.md)에 계약과 근거를 기록한다. 각 옵션은 GET 응답에서 유효한 값을 확인한 경우에만 기기에 보낼 수 있다. 미연결 모델 선택은 예시이며 실제 기기 지원을 보증하지 않는다.

버튼 설정에는 Normal/Reverse라는 이름만 두지 않는다. 하나의 기기 그림에 해당 물리 버튼과 이전 쪽·다음 쪽·페이지 넘기지 않음 결과를 보여 준다. 별도의 같은 대응표와 위치 설명을 반복하지 않는다. 방향 변경 후 결과도 함께 바뀐다. 상하·좌우는 모델과 방향에 맞는 실제 의미를 사용한다. 회전 정책의 추가 설명은 필요할 때 연다.

읽기 방향은 기기의 세로·가로 회전이다. 텍스트 세로쓰기 기능을 추가하지 않는다. 앱의 독서 외관은 기존 전체 책 기본값을 유지하며 기기 옵션과 별도로 즉시 반영한다.

## 공통 내용과 권한

내 카드와 날씨·일정은 Reader settings의 홈/대기 화면 공통 원본 요약 행에서 각각 전용 편집 화면으로 바로 연다. 부모 Home/Sleep 폼에 원본 편집 폼과 적용 버튼을 펼쳐 놓지 않는다. 각 원본 편집 화면은 자체 제목·미리보기 또는 현재 값·영향 범위·저장 상태·하나의 적용 행동을 제공한다. 닫기와 연결 복귀 후 부모의 선택과 초안이 보존된다. 카드 편집과 배포는 기존 초안 저장·충돌·복구·ContentDeployment를 사용한다. Home/Sleep에 영향을 줄 수 있음을 짧게 표시하며 Reading 변경을 포함하지 않는다.

날씨 지역과 캘린더 선택은 앱에 저장한다. 원본 변경 또는 미리보기 갱신만으로 기기에 전송하지 않는다. 사용자의 설정 행동에 따른 날씨 조회는 가능하지만 기기 반영은 해당 원본 편집 화면의 명시적 적용으로 한다. 기존 자동 갱신 동작과 사용자의 새 원본 편집이 충돌하지 않도록 로컬 미적용 변경을 구분한다.

일정은 기본값으로 기존의 모든 캘린더를 유지한다. 사용자가 원하면 캘린더를 선택하고, 빈 선택은 일정이 없음을 분명히 보여 준다. 삭제됐거나 접근할 수 없는 캘린더를 조용히 다른 캘린더로 대체하지 않는다. 권한은 관련 기능을 켜거나 캘린더를 고르는 순간 요청하며 데모에서는 요청하지 않는다. 거부 상태에서는 시스템 설정으로 가는 행동과 다시 확인을 제공한다.

Weather의 주 내용은 날씨다. 공급자 로고는 기존 콘텐츠를 가리지 않는 보조 크기와 위계로 둔다. 출처·법적 표시는 필요한 요구사항을 충족하되 사용자 설정 항목과 같은 강조를 주지 않는다. 요구사항을 확인 없이 제거하지 않는다.

## Manage reader와 앱 설정

Manage reader의 주 그룹은 Connection, Continue Reading 연결, Firmware, 기기 정보와 문제 해결이다. 같은 Wi-Fi 경로를 먼저 제안하고 다른 방법은 필요할 때 펼쳐 선택한다. 직접 연결이 Apple 기기의 Wi-Fi를 변경한다면 선택 전에 설명하며 기존 승인 절차를 유지한다. Wi-Fi로 가능한 일을 불필요한 Bluetooth 등록으로 막지 않는다.

펌웨어는 호환 확인·파일 준비·전달·기기에서 설치 확인·재연결 후 검증 단계로 보여 준다. 연결된 상태의 Update 확인은 다운로드·검증·해당 연결로 보내기를 함께 승인하는 기존 동작을 유지하고, 확인 문구에서 이 범위를 알린다. Download update for later는 로컬 준비만 하며 이후 연결과 Send update 확인으로 이어진다. 전달 완료를 설치 완료로 표시하거나 자동 플래시하지 않는다. 고급 진단과 개발용 항목은 기존 플랫폼·빌드 범위를 유지한다.

앱 설정은 외관의 직접 조절, 이어 읽기 정책, 자동 재연결, 개인정보·권한·도움말로 구성한다. 실제 pairing은 Manage reader에서 관리하고 Settings에서는 상태와 해당 위치로 이어지는 행동을 제공한다. 책 파일 공유와 읽던 위치 공유는 다른 기능임을 행동과 명칭으로 구별한다.

## 통합과 완료 판정

세 구현 영역은 전송 실행 계층, 셸과 작업 UI, 편집과 공통 내용이다. 기존 저장 데이터와 미커밋 작업을 보존하고 각 영역이 소유한 파일을 통해 변경한다. 프로젝트 생성과 통합 빌드, 테스트, 스크린샷 재생성은 루트가 순차적으로 조율한다.

완료에는 화면 명세의 B01–B15, 내 리더의 상태별 행동, 편집 범위 분리와 초안 이행, 캘린더 선택과 데모 비변경, 양 플랫폼 빌드, 관련 회귀 테스트, 실제 앱 UI 스크린샷 확인이 포함된다. 물리 연결과 기기 설치·패널 동작은 별도 수용 여부를 보고한다. 첫 부분 구현을 전체 완료로 보고하지 않는다.
