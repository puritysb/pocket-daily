# Pocket Daily 구현 정리 — 2026-09-24

목표는 CrossPoint의 독서 기반 위에서 앱으로 콘텐츠와 지원되는 UI를 편집하고,
같은 세션에서 변경분 적용과 실제 화면 완료를 확인하는 것이다. 일상적인
콘텐츠 변경에는 펌웨어 설치나 네트워크 재연결이 필요하지 않아야 한다.

게임 제거가 Sync의 런타임 메모리 부족을 해결했다고 주장하지 않는다. 게임
Activity는 열었을 때 할당되며, 이번 화면 표시 성공은 앞선 서버 라우트 수명
개선으로 얻은 별도 결과다. 게임 제거의 크기 변화는 빌드 수치로만 비교한다.

## 완료 응답 대기

기기가 `queued`를 확인한 뒤 폰트 준비 중 HTTP 응답이 지연돼도 앱은 첫 통신
실패를 곧바로 표시 실패로 처리하지 않는다. 2초 간격, 최대 45회, 단조 시계
90초 예산 안에서 GET만 재시도한다. 마지막에 이미 시작한 HTTP 요청은 기존
15초 요청 제한을 따르므로 정확한 90초 강제 종료는 아니다. 연결 변경,
업로드·활성화·표시 POST 재전송은 없다. 취소, 잘못된 기기/리비전/세대,
실패 응답은 즉시 중단한다. POST 거절과 응답 유실의 기존 복구 의미는 유지한다.

이것은 표시 완료 확인의 개선이지 기기의 긴 준비 시간 자체를 단축한 것은
아니다. 펌웨어의 준비 단계별 시간 계측과 제한된 폰트/저장 접근 개선이 뒤따라야 한다.

## 다음 완료 기준

1. 정리본 설치와 Sync 자동 복귀는 완료. 첫 적용의 rendered 응답은 확인됐으나
   후속 수정은 저장 활성화 후 메모리 부족으로 화면 갱신 실패. 메모리 수명을
   수정하고 같은 세션에서 반복 적용의 응답과 실물 화면을 확인한다.
2. 준비 중 취소·응답 지연·연결 손실 후 저장된 활성 콘텐츠를 보존하고,
   불필요한 업로드·재부팅·네트워크 전환이 없는지 확인한다.
3. AgentDeck의 별도 OTA/제공자 경로는 기본 제품 업데이트 경로와 분리 검토한다.
   기본 비활성이라는 이유만으로 생산 배포 안전성 검증이 끝난 것은 아니다.
4. 직접 연결은 사용자가 선택한 별도 실기기 시험으로 수행한다. X4와 iPhone의
   무선 수용은 X3/Mac 성공으로 대체하지 않는다.

설치는 완료했지만 반복 적용의 하드웨어 수용은 실패했다. 다음 작업의 우선순위는
[NEXT_STEPS.md](NEXT_STEPS.md)를 따른다.
