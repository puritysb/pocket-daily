# Pocket Daily 제품 개선 백로그

작성일: 2026-09-25. 앱·펌웨어 공동 작업을 위한 제품 검토 문서.

사용자가 제시한 13개 제안과 코드·계약·업스트림 검토 의견을 정리했다.
우선순위는 권장안이며 출시 약속이나 전체 구현 착수 승인이 아니다.
이 문서 작성 시점에는 기존 개선 작업이 다른 세션에서 진행 중이다.
관찰한 미커밋 소스를 출시된 기능으로 취급하지 않는다.

## 문서의 역할과 작업 원칙

- 현재 진행 중인 안정화·실기기 수용은 [NEXT_STEPS.md](NEXT_STEPS.md)를 따른다.
  그 문서의 핵심 경로 수용 전에 이 백로그로 주변 기능을 확대하지 않는다.
- 변경 불가 제약과 검증 규칙은 각 저장소의 `AGENTS.md`, 확인된 이력은
  [PROJECT_MEMORY.md](PROJECT_MEMORY.md), 기능별 형식은 해당 계약 문서가 기준이다.
- 이 문서는 앱 저장소가 소유하는 공동 백로그다. 펌웨어 세션에서는 형제 경로
  `../pocket-daily/docs/PRODUCT_BACKLOG.md`로 읽는다. 다른 저장소에 복제하지 않는다.
- 계정 없이 로컬에서 준비하고 명시적으로 전송하는 흐름을 유지한다.
  AgentDeck·서버·상시 무선을 필수 조건으로 만들지 않는다.
- 기기는 읽기·표시·로컬 기록, 앱은 수집·변환·편집·복습 관리에 집중한다.
- 문서화 승인과 커밋·푸시·기기 설치·스토어 제출 승인은 별개다.

## 작업별 범위와 완료 기준

### PD-01 / PD-04 — 읽을거리 보내기

- 첫 버전: 사용자가 고른 HTML/텍스트·기사 URL을 가져와 본문을 확인하고,
  제목·출처·목차를 갖춘 EPUB로 만든 뒤 기존 준비 목록과 전송 경로를 사용한다.
  여러 기사 묶기는 동일한 EPUB 생성기를 공유한다.
- 앱에서 변환을 끝내고 기기는 기존 읽기 엔진을 사용한다. 인터넷이 필요한
  수집과 인터넷 없이 가능한 준비 파일 전송을 구분한다.
- DOCX는 문단·제목·기본 이미지 지원을 후속 범위로 정한다. PDF는 텍스트 중심
  문서부터 별도 평가한다. 스캔 OCR, 다단·표·수식 복원까지 첫 버전에 넣지 않는다.
- 자동 뉴스 수집, AI 요약, 로그인 페이지 처리와 유료벽 우회는 초기 범위 밖이다.
- 완료 기준: 한글/영문·이미지·목차·긴 본문 표본의 생성/재열기/기기 읽기,
  지원하지 않는 입력 안내, 취소·실패 시 원본 보존, 앱 재실행 후 전송 준비 보존.
- 근거: [TextDocument.swift](../Sources/TextDocument.swift)는 입력 텍스트의 TXT
  생성 기반이다. EPUB 생성이나 범용 문서 변환이 이미 구현됐다는 뜻은 아니다.

### PD-02 — 로컬 독서 통계

- 기기에서 독서 세션과 추정 활동 시간을 기록하고 홈·슬립에 작은 요약을 표시한다.
  방치 시간 제외 기준과 페이지 넘김/되돌아감의 집계 의미부터 정의한다.
- 페이지 수는 글꼴·화면 설정에 따라 바뀐다. 고정된 독서량처럼 표현하지 않는다.
  세션 시간은 단조 시계, 날짜 묶음은 유효한 달력 시각을 사용하고 시각 미확정
  상태도 처리한다. X4의 날짜 신뢰성을 X3와 같다고 가정하지 않는다.
- SD 기록은 매 입력마다 하지 않고 제한된 주기·종료 시점에 저장한다.
- 완료 기준: 유휴·날짜 변경·시각 보정·전원 중단·재열기의 집계 규칙 검증,
  기록 크기 상한, 독서 중 지연 및 소비전력 회귀 없음.

### PD-03 — 앱이 만드는 브리프

- 앱에서 선택한 캘린더의 가까운 일정과 지정 지역의 날씨를 준비해 명시적으로
  보낸다. 첫 버전은 예약/백그라운드 동기화를 약속하지 않는다.
- 앱 담당: 권한 요청, 캘린더 선택, 날씨 공급원·비용·표시 조건 검토,
  전송 전 확인과 로컬 보관/삭제 정책. 위치 권한 없이 지역 지정부터 검토한다.
- 펌웨어 담당: 제한된 크기의 데이터 검증·저장·홈/슬립 표시, 오래된 정보 표시.
- 공동 계약: 버전, capability, 생성 시각, 시간대, 유효기간, 필드/개수 상한,
  원자적 교체, 기존 공급자와의 우선순위, 데이터 삭제와 구형 펌웨어 처리.
- 완료 기준: AgentDeck 없이 전체 흐름 성공, 권한 거절·빈 일정·네트워크 실패·
  만료 데이터 처리, 이전 정상 데이터 보존, X3/X4 표시 확인.
- 근거: 펌웨어 [models.h](../../pocket-daily-firmware/src/pocket_daily/models.h)의
  Glance와 [프로필 계약](../../pocket-daily-firmware/docs/pocket-profile-v1.md).
  화면 배치 설정이 존재하는 것과 앱 데이터 공급이 완성된 것은 다르다.

### PD-05 — 책 끝의 다음 책 제안

- 같은 폴더의 다음 책 또는 최대 3개 후보를 제안하고 사용자가 고른 뒤 연다.
  추천 규칙·정렬·현재 책 제외·빈 폴더 동작을 명시한다. 자동 열기는 제외한다.
- 업스트림 [PR #2532](https://github.com/crosspoint-reader/crosspoint-reader/pull/2532)
  를 출발점으로 의존 변경을 검토한다. 현재 책 진행도와 뒤로 가기를 보존한다.
- 완료 기준: 단일 책/다수 책/긴 파일명/손상 파일에서 정상 동작,
  큰 폴더에서도 메모리 상한 유지, 마지막 페이지와 메뉴 입력 충돌 없음.

### PD-07 — 오프라인 사전

- 버튼 기반 단어 선택→뜻 보기→원래 페이지 복귀를 먼저 완성한다.
  초기 언어·사전 형식·사전 파일 공급/라이선스·설치 UX를 착수 시 확정한다.
- 앱은 사전 준비와 설치를 보조할 수 있다. 기기 조회에 인터넷을 요구하지 않는다.
- 업스트림 [1.5 발표](https://github.com/crosspoint-reader/crosspoint-reader/discussions/2693)
  에 구현 근거가 있으나, 포크의 EPUB·한글 폰트·메모리 호환 검증은 별도다.
- 완료 기준: 실제 한글/영문 책의 선택 UX, 미등록 단어·긴 정의·손상 사전,
  연속 조회 후 메모리 회수, 페이지/진행도 보존, 네트워크 없이 동작.

### PD-09 — 단어 저장부터 앱 복습까지

- PD-07 이후 단어·문맥·책 식별자·위치를 기기에 저장한다. 저장 한도와 중복 규칙,
  앱으로 읽어오는 계약 및 삭제/충돌 규칙을 먼저 정한다.
- SRS 일정·편집은 앱에 두고 기기는 오늘의 복습 카드 표시부터 검토한다.
  기존 일일 단어/학습 카드와 별도 기능을 중복 생성하지 않는다.
- 완료 기준: 재부팅 후 보존, 재동기화 중복 없음, 삭제 반영, 개인정보 노출 없는
  로컬 보관, 복습 일정의 결정적 시험. 저장과 SRS는 별도 완료 단위다.

### PD-10 — 연결된 기기의 한 번 탭 동기화

- 이미 연결됐거나 기기가 명시적으로 동기화 대기 중일 때, 준비한 변경분을
  한 번의 사용자 동작으로 보낸다. 현재 단일 Send와 중복되는 부분은 먼저 확인한다.
- 중복 탭 방지, 진행·취소·재시도, 대상 기기 확인을 기존 전송 경로에서 해결한다.
- 잠든 기기를 BLE로 깨우는 기능은 포함하지 않는다. 현재 BLE 광고는 Sync 화면에서만
  시작한다. [Nearby Sync 계약](../../pocket-daily-firmware/docs/nearby-sync-v1.md)
- 완료 기준: 연결/미연결/중단/구형 기기 동작과 명시적 직접 연결 동의를 보존하고,
  LAN 탐색이 임의로 Apple 기기의 Wi-Fi를 바꾸지 않는다.

### PD-11 — 읽기 설정 결과 확인과 툴바

- 두 작업으로 나눈다. 먼저 실제 읽기 설정의 결과를 짧은 경로로 확인하고
  취소할 수 있게 한다. 글꼴 변경 시 캐시 재생성과 진행도 보존을 검증한다.
- 툴바는 X3/X4 버튼 입력·작은 화면에서의 이득을 확인한 뒤 채택한다.
- 업스트림 [1.6 변경 내역](https://github.com/crosspoint-reader/crosspoint-reader/releases/tag/1.6.0)
  에 툴바와 버튼 기기 설정 숨김 수정이 함께 있다. 글자 설정 라이브 미리보기의
  정확한 포트 대상은 아직 미확정이다. 착수 전에 커밋과 의존성을 고정한다.
- 완료 기준: 네 방향·X3/X4·한글 폰트에서 입력과 표시 확인, 설정 취소/복귀,
  책 진행도 유지, 과도한 페이지 재생성·깜박임 방지.

### PD-13 — 측정 기반 배터리 개선

- 전면 재설계를 미리 결정하지 않는다. 독서 대기·페이지 넘김·홈 대기·동기화·
  완전 종료·타이머 절전을 나누어 전류와 소요 시간을 측정한다.
- 동일 기기·배터리 조건·책·폰트·넘김 주기·무선 상태로 전후 비교한다.
  배터리 백분율만으로 개선을 주장하지 않는다.
- CPU/무선/SD/센서/디스플레이 수명과 종료 경로에서 측정된 병목부터 수정한다.
  앱도 불필요한 요청과 세션 유지 시간을 줄일 수 있으나 실측으로 판단한다.
- 완료 기준: 재현 가능한 기준선과 전후 결과, 독서 응답·깨우기·진행 저장·전송
  회귀 없음. X3/X4를 구분하고 미보유 기기의 결과를 추정으로 대체하지 않는다.
- 근거: [HalPowerManager.cpp](../../pocket-daily-firmware/lib/hal/HalPowerManager.cpp).
  완전 종료와 전원을 유지하는 타이머 절전이 이미 별도 경로다.

## 보류 항목의 재개 조건

### PD-06 — 앱에서 EPUB 캐시 생성

- 현재 [Live Studio 계약](../../pocket-daily-firmware/docs/live-studio-v1.md)은 EPUB
  레이아웃·페이지 캐시를 기기 소유로 둔다. 변경하려면 별도 설계 결정이 필요하다.
- [캐시 규칙](../../pocket-daily-firmware/lib/Epub/AGENTS.md)에 따라 경로 해시,
  형식 버전, 글꼴, 화면 크기/방향, 읽기 설정을 맞춰야 한다. 홈·카드 호스트
  렌더러가 곧 EPUB 캐시 생성기는 아니다.
- 재개 조건: 실제 첫 화면 지연의 병목 측정, 기존 증분 캐시와 입력 EPUB 최적화로
  부족하다는 근거, 호스트 생성 비용 대비 효과, 버전 협상·잘못된 캐시 거절·
  기기 자체 재생성 fallback·원자적 반입 설계 확보.

### PD-08 — 아침 브리프 자동 갱신

- X3의 RTC 존재만으로 완전 전원 차단 후 알람 부팅이 가능하다고 단정하지 않는다.
  알람 배선/전원 경로를 확인한다. 기존 타이머 절전은 대기 전류 비용이 있다.
- 기기가 깨어나는 것과 새 데이터를 받을 수 있는 것은 별개다. 폰의 정시
  백그라운드 실행은 보장되지 않는다.
  [Apple 설명](https://developer.apple.com/videos/play/wwdc2019/707/)
- 재개 조건: PD-03 수동 갱신 수용, PD-13 소비전력 기준선, 데이터 공급 상대의
  가용성, 실패 후 제한된 재시도와 절전 복귀, 저전력/오래된 데이터 처리.
  사전 전송한 브리프의 예약 표시와 최신 데이터 다운로드는 별도 범위로 판단한다.

### PD-12 — 뒤집기·탭 제스처

1. 작업 시작 전에 현재 트리·진행 중인 세션의 담당 범위와 이 문서를 확인한다.

2. PD-01/04는 같은 변환 기반을 공유한다. 별도 세션이라면 EPUB 생성 계약을 먼저
   정하고 수집 UI와 생성기를 나눈다. PD-03과 PD-09의 프로토콜·저장은 양쪽
   담당을 명시하고 계약부터 검토한다.
3. PD-05/07/11은 리더 입력·메뉴·EPUB 코드를 함께 건드릴 수 있다. 독립 구현으로
   간주하지 말고 파일 소유권을 나누거나 순서를 정한다. PD-13 전력 변경과
   PD-08/12 센서·깨우기 변경도 겹치므로 측정 기준을 먼저 고정한다.
4. 계약 변경은 버전/capability, 크기 상한, 검증, 구형 기기, 실패 복구를 문서화하고
   앱·펌웨어 양쪽 테스트를 포함한다. 한쪽 구현만으로 완료하지 않는다.
5. 완료 기록에는 실제 실행한 검사와 미검증 실기기 항목을 구분한다. 각 AGENTS의
   빌드·테스트·UI 스크린샷·메타데이터 검증 요구를 따른다. 기능 후보를 먼저
   스토어 설명에 넣지 않는다.
6. 이 문서의 상태는 인수인계 때 갱신한다. 확정된 계약·검증 기준선만 해당 변경과
   함께 PROJECT_MEMORY에 남긴다. 문서화만으로 구현 완료나 출시를 표시하지 않는다.

상태는 `미착수 → 설계 중 → 구현 중 → 로컬 검증 → 실기기 수용 대기 → 완료`를
