# Pocket Daily 제품 IA

작성일: 2026-10-05, 내비게이션 개정: 2026-10-09. 상태: 이번 구현의 IA 기준. 화면과 상태의 상세 결정은 [IA 구현 설계](IA_FINAL_DESIGN.md)에 확정했다.

Pocket Daily의 두 목적, **앱에서 읽기**와 **리더 기기 활용**을 동등하게 지원하는 정보 구조를 정한다. 사용자가 무엇을 읽고 싶은지, 기기에서 무엇을 바꾸고 싶은지를 먼저 선택하고, 연결과 전송은 그 일을 수행하는 과정에서 이어지도록 설계한다.

이 문서는 정보의 소속, 주요 진입점, 과업의 연결 관계를 정하는 설계 기준이다. 구현과 검증 결과는 [구현 보고](IA_IMPLEMENTATION_REPORT.md)에 기록한다. 기존 제품 원칙과 승인된 통신 계약을 유지한다.

구체적인 화면 책임과 첫 전송 시나리오는 [화면과 작업 흐름 명세](PRODUCT_UX_SPEC.md), 기존 코드 활용과 개발 순서는 [IA 전환 계획](IA_MIGRATION_PLAN.md)에 정리했다.

## 확정된 제품 방향

- 앱 독서와 기기 활용은 동등한 핵심 경험이다. 이는 이번 IA 논의에서 사용자가 확인한 방향이다.
- 서재와 앱 독서는 기기, 계정, 인터넷 없이 사용할 수 있어야 한다. 첫 진입은 서재이며, 기기 활용도 같은 수준에서 발견할 수 있어야 한다.
- 대상은 Pocket Daily 또는 호환 펌웨어를 사용하는 X3/X4다. 제조사 기본 펌웨어와의 호환성을 전제하지 않는다.
- 책 파일의 보관과 읽던 위치의 공유는 서로 다른 일이다. 다른 곳의 읽던 위치가 도착해도 현재 페이지를 임의로 이동하지 않는다.
- 연결, 전송, 펌웨어 설치에는 각각의 상태가 있다. 연결 성공을 전송 성공으로, 펌웨어 전달을 설치 완료로 표현하지 않는다.

제품 원칙은 [AGENTS.md](../AGENTS.md), 독립 독서와 기기 중심 구조의 기존 결정은 [READER_EXPANSION.md](READER_EXPANSION.md)를 따른다.

## 사용자가 하려는 일

| 사용자 목적 | 시작하는 곳 | 완료됐다고 느끼는 시점 |
| --- | --- | --- |
| 책이나 저장한 글을 앱에서 읽는다 | 서재 | 원하는 내용을 열고 읽던 곳에서 읽는다 |
| 앱과 리더를 오가며 읽는다 | 책 또는 이어 읽기 안내 | 같은 책을 확보하고, 제안된 위치를 확인해 이어 읽는다 |
| 리더에 읽을 거리를 넣는다 | 서재 또는 기기 보관함 | 선택한 파일이 해당 리더에 들어갔음을 확인한다 |
| 리더의 홈과 대기 화면을 꾸민다 | 내 리더의 화면 꾸미기 | 바뀔 모습을 이해하고 리더에 반영한다 |
| 리더에서 편하게 읽도록 조정한다 | 내 리더의 읽기 방식 | 방향, 글자, 버튼의 효과를 이해하고 반영한다 |
| 기기를 연결하거나 관리한다 | 내 리더 또는 진행 중인 작업 | 연결 문제를 해결하거나 업데이트 상태를 확인한다 |

연결 방법이나 전송 프로토콜을 먼저 고르게 하지 않는다. 과업에 필요한 조건을 확인하고 그에 맞는 연결 방법을 안내한다.

## 제안하는 최상위 구조

주요 목적지는 **서재**와 **내 리더** 두 곳이다. 앱 설정은 별도의 보조 진입점으로 둔다. 두 목적을 동등하게 지원한다는 것은 두 목적지가 늘 발견 가능하다는 뜻이며, 같은 수의 하위 메뉴를 만들거나 첫 실행에서 사용 모드를 선택하게 한다는 뜻은 아니다.

```text
Pocket Daily
├─ 서재
│  ├─ 읽던 책과 글
│  ├─ 전체 콘텐츠 · 검색 · 분류
│  └─ 책이나 글
│     ├─ 앱에서 읽기 → 읽기 화면과 앱 읽기 설정
│     ├─ 리더로 보내기
│     └─ 보관 위치와 읽던 위치
│
├─ 내 리더
│  ├─ 첫 화면: 기기 상태 · 진행 중인 작업 · 기기 보관함
│  ├─ 기기 설정 (Reader Settings)
│  │  ├─ 홈 화면 · 대기 화면
│  │  ├─ 독서 설정 (Reading Preferences): 본문 모양 · 방향 · 버튼
│  │  └─ 사용할 내용 → 내 카드 · 날씨 · 일정
│  └─ 기기 옵션 메뉴 → 기기 관리 (Manage Reader)
│     ├─ 등록과 연결
│     ├─ 펌웨어 업데이트
│     └─ 기기 정보와 문제 해결
│
└─ 앱 설정
   ├─ 앱 외관과 동작
   ├─ 이어 읽기 정책
   └─ 개인정보와 권한 · 도움말 · 앱 정보
```

이 트리는 정보의 소속을 나타낸다. 모든 항목을 탭이나 버튼으로 노출하라는 화면 설계가 아니다. ‘읽기’는 서재에서 콘텐츠를 열어 들어가는 집중 화면이며, 세 번째 최상위 메뉴로 중복하지 않는다.

휴대폰에서는 두 목적지를 같은 수준의 내비게이션에, 넓은 화면에서는 사이드바의 두 주요 영역에 배치하는 안을 제안한다. 읽기와 편집은 작업하던 창 안에서 이어지고, 창 크기가 달라져도 명칭과 정보의 소속은 유지한다. 세부 배치와 다중 창 동작은 화면 명세에서 정한다.

## 정보별 책임과 경계

| 정보 | 주 관리 위치 | 다른 곳에서 접근할 때의 원칙 |
| --- | --- | --- |
| 책과 저장한 글 | 서재 | 기기 보관함에서도 같은 콘텐츠인지 식별한다 |
| 책을 읽던 위치 | 해당 책 | 서재와 읽기 화면에서 이어 읽기를 제안한다 |
| 앱에서 읽는 모양 | 앱 읽기 화면 | 앱에 적용됨을 명시하고 기기 설정과 분리한다 |
| 리더에 실제로 있는 파일 | 기기 보관함 | 서재에는 해당 리더에 있는지 요약한다 |
| 홈과 대기 화면 구성 | 내 리더의 화면 꾸미기 | 하나의 편집 방식으로 두 화면을 다룬다 |
| 카드 내용과 날씨 및 일정 선택 | 화면 꾸미기의 사용할 내용 | 홈과 대기 화면은 같은 내용의 사용 위치를 지정한다 |
| 리더의 독서 방향과 버튼 동작 | 내 리더의 읽기 방식 | 선택한 기기와 지원 범위를 기준으로 표시한다 |
| 기기 신원과 연결 정보 | 내 리더의 기기 관리 | 각 작업의 연결 안내는 이 정보를 공유한다 |
| 읽던 위치 공유 여부 | 앱 설정의 이어 읽기 | 책과 기기 화면에는 현재 상태와 관련 바로가기를 둔다 |
| 작업 진행과 복구 | 진행 중인 작업 | 출발 화면으로 돌아와도 같은 작업을 이어 본다 |

앱 서재와 기기 보관함은 같은 목적의 두 서재가 아니다. 전자는 읽을 콘텐츠를 중심으로, 후자는 특정 기기에 저장된 파일을 중심으로 보여 준다. 같은 책이 양쪽에 있으면 보관 위치를 함께 표시하고, 기기에만 있는 책은 ‘앱으로 가져오기’로 연결한다. 실제 가져오기 지원 여부는 기기 기능에 따라 확인한다.

삭제는 대상이 분명해야 한다. ‘서재에서 삭제’와 ‘리더에서 삭제’를 구분하며 한쪽의 삭제를 다른 쪽으로 자동 전파하지 않는 것을 제안한다. 읽던 위치 공유에도 파일 복제나 삭제의 의미를 포함하지 않는다.

## 서재와 앱 독서

서재의 첫 화면에서는 읽던 콘텐츠와 전체 콘텐츠에 바로 접근한다. 책과 글은 필요할 때 분류해 보되, 읽기와 보내기 동작은 같은 방식으로 제공한다. 가져오기와 글 추가는 서재의 콘텐츠 추가 흐름에 속한다.

콘텐츠를 열면 앱에서 바로 읽는다. ‘리더로 보내기’는 책의 보조 행동으로 발견할 수 있게 한다. 기기가 없어도 읽기 행동은 완전하게 동작하며 연결 안내가 이를 가리지 않는다.

앱 읽기 설정은 실제 페이지를 보며 조정한다. 글자, 여백, 페이지 색상 등은 즉시 앱에 반영하고 별도 Apply를 요구하지 않는다. 이번 전환에서는 전체 책의 기본값을 유지하고 화면에 범위를 표시한다. 책별 외관 예외는 후속 제품 범위다.

기기의 읽던 위치가 도착하면 책과 위치를 알아볼 수 있는 이어 읽기 제안을 보여 준다. 사용자는 이동하거나 현재 위치를 유지한다. 더 높은 퍼센트를 무조건 최신으로 간주하지 않는다. 파일이 없는 경우에는 책 확보가 먼저임을 안내한다. 자세한 연속 독서 계약은 [READING_PROGRESS.md](READING_PROGRESS.md)를 따른다.

## 내 리더의 첫 화면

내 리더는 연결 상태만 보여 주는 화면이 아니라 기기를 사용하는 출발점이다. 기기 이름과 모델, 확인 가능한 상태, 지금 필요한 행동과 기기 보관함을 같은 첫 화면에서 보여 준다. Reader Settings는 기기 카드에서, Manage Reader는 기기 옵션 메뉴에서 연다. Overview·On Reader·Screens·Reading·Device를 각각 주 내비게이션에 두지 않는다.

My Reader의 기기 선택 메뉴에서 등록한 리더와 각각의 상태를 확인하고 추가·이름 변경·전환한다. 같은 Wi-Fi에 있는 여러 리더는 연결을 유지하며 독립적으로 작업할 수 있다. 대상 전환은 전송 취소나 초안 이동을 뜻하지 않는다. 설정 초안·카드·날씨와 일정 선택·전송 대기열·Bluetooth 기록은 등록별로 보존하고, 서재의 책과 읽던 위치 공유는 앱 공통으로 유지한다. 등록 삭제는 연결 및 현재 작업이 끝난 뒤 가능하며 기기 파일이나 서재를 삭제하지 않는다.

| 상태 | 먼저 보여 줄 정보와 행동 |
| --- | --- |
| 아직 등록한 기기가 없음 | 리더 연결, 호환 기기 안내, 연결 없이 화면 꾸며보기 |
| 등록한 기기가 연결되지 않음 | 기억한 기기, 마지막 확인 시점, 연결하기, 저장된 편집 계속하기 |
| 읽던 위치만 교환할 수 있음 | 이어 읽기 상태. 파일이나 설정을 보낼 때 필요한 연결을 안내 |
| 파일과 설정을 보낼 수 있음 | 사용 가능한 작업과 확인된 기기 상태 |
| 전송 또는 업데이트가 진행 중 | 해당 작업의 단계와 다음 행동 |
| 연결이나 작업이 실패함 | 보존된 작업 내용, 원인에 맞는 재시도 또는 연결 변경 |

‘연결됨’ 하나로 모든 기능의 사용 가능 여부를 표현하지 않는다. 사용자가 알아야 하는 것은 현재 이 기기로 무엇을 할 수 있는지다. 연결되지 않은 기기의 배터리, 파일 목록, 설정에는 마지막으로 확인한 정보임을 표시한다.

기기 관리에 연결의 상세 화면을 두되, 보내기나 적용하기 중 연결이 필요하면 해당 작업 안에서 연결한다. 사용자를 별도 메뉴에 보내 놓고 작업을 다시 찾게 하지 않는다.

## 화면 꾸미기와 읽기 방식

화면 꾸미기와 독서 설정은 하나의 Reader Settings 안에서 편집 범위를 선택한다. Reading이라는 독립 메뉴는 두지 않는다. **미리보기, 관련 조정 항목, 저장 및 반영 상태, 하나의 적용 행동**을 같은 위치 관계로 제공한다. 한 화면 안에 여러 Apply 버튼이나 중첩된 선택 막대를 늘어놓지 않는다.

### 화면 꾸미기

홈과 대기 화면은 같은 종류의 편집 대상이다. 편집할 화면을 한 번 선택하면 그 화면의 미리보기와 관련 옵션이 함께 바뀐다. 카드, 날씨, 일정은 해당 화면에서 사용할 내용이며, 각각 독립적인 최상위 목적지가 되지 않는다.

카드 원본은 ‘내 카드’에서 관리하고 홈과 대기 화면에서는 어느 카드를 어떻게 보여 줄지 정한다. 카드 본문 변경이 여러 화면에 영향을 준다면 사용 중인 화면을 알려 준다. 카드의 독립적인 작성·배포 경험을 확장할지는 이후 제품 결정으로 남긴다.

날씨의 지역과 일정의 캘린더 선택은 ‘사용할 내용’에서 관리하는 안을 제안한다. 홈과 대기 화면은 그 내용을 사용할지와 배치를 정한다. 화면마다 다른 원본 설정을 복제하지 않는다. 플랫폼 권한 상태는 앱 설정에서도 확인할 수 있지만, 실제 설정과 권한 요청은 관련 내용을 켜는 순간 이어진다.

날씨 정보에서는 날씨가, 일정에서는 일정이 시각적 중심이어야 한다. 공급자 표시와 출처는 필요한 의무를 확인해 충족하면서 낮은 시각적 위계로 배치한다. Apple Weather 표시의 구체적인 크기와 링크 위치는 제공자 요구사항을 확인한 뒤 화면 명세에서 정한다.

### 읽기 방식

기기에서 책을 읽는 방법을 조정한다. 항목 수를 늘리는 것보다 사용자가 결과를 예측할 수 있는 옵션을 우선한다.

| 조정하려는 것 | 제안하는 표현 | 명세 전 확인할 사항 |
| --- | --- | --- |
| 리더를 가로 또는 세로로 들고 읽기 | 화면 방향과 함께 회전하는 책 미리보기 | 모델 및 펌웨어별 방향 지원 |
| 본문을 편하게 읽기 | 글자 크기·줄 간격·여백의 결과가 보이는 예시 | 실제 지원 항목과 값의 범위 |
| 어느 버튼으로 다음 쪽을 넘길지 정하기 | 실제 기기 모양 위에 ‘이전 쪽’과 ‘다음 쪽’ 표시 | X3/X4의 버튼 위치, 방향별 매핑, 변경 가능 범위 |

‘Page-turn buttons’나 ‘Normal/Reverse’만으로 동작을 설명하지 않는다. 선택한 기기의 실제 버튼 위치와 누른 결과를 함께 보여 준다. X3와 X4에 동일한 그림이나 고정된 좌우 설명을 재사용하지 않는다.

‘화면 방향’은 세로·가로 회전을 뜻한다. 글의 가로쓰기·세로쓰기는 별도 기능이며, 방향 전환에 포함된다고 암시하지 않는다. 기기와 펌웨어의 지원이 확인되지 않은 옵션은 사용 가능하다고 약속하지 않는다.

### 저장과 적용의 공통 규칙

- 앱 읽기 설정은 실제 앱 페이지에 즉시 반영한다.
- 기기 편집은 연결 없이도 저장하고 미리 볼 수 있게 한다. ‘앱에 저장됨’과 ‘리더에 반영됨’을 분리한다.
- 기기 편집의 주 행동은 ‘리더에 적용’으로 통일한다. 적용 범위는 현재 작업으로 한정하고, 변경 요약에서 대상을 보여 준다. 화면 꾸미기를 적용하면서 별도 작업인 읽기 방식까지 묵시적으로 보내지 않는다.
- 연결이 필요하면 같은 작업 안에서 연결을 안내한다. 연결만 완료했다고 변경사항을 자동 전송하지 않는다.
- 연결 후 기기 값과 편집 중인 값이 다르면 수정한 내용을 보존한다. 충돌이 있는 부분만 비교할 수 있게 한다.
- 미리보기는 적용 전부터 제공한다. 실제 기기 화면을 가져온 것이 아니라면 이를 구별하고, 책 미리보기는 실제 글꼴·페이지 나눔과 다를 수 있음을 짧게 표시한다.
- 성공 표시는 확인된 단계까지만 한다. 저장, 전송, 기기 반영, 실제 표시 여부가 다르면 같은 완료 문구를 쓰지 않는다.

## 연결과 전송을 잇는 흐름

연결은 두 곳에서 시작할 수 있다. 기기를 처음 등록할 때는 내 리더에서, 이미 하려는 일이 있을 때는 해당 작업에서 시작한다. 두 경로가 공유하는 연결 경험을 만들고 작업의 대상과 편집 내용을 유지한다.

| 시나리오 | 제안하는 흐름 |
| --- | --- |
| 처음 앱에서 읽기 | 서재 → 책 추가 → 읽기. 기기 등록 단계 없이 완료 |
| 리더 처음 사용하기 | 내 리더 → 호환성 안내 → 기기 찾기 및 식별 → 필요한 연결 → 기기 요약 |
| 연결 없이 책 보내기 시작 | 책 선택 → 리더로 보내기 → 대상과 연결 안내 → 연결 → 선택한 책 보내기 → 결과 |
| 연결 없이 홈 꾸미기 | 화면 꾸미기 → 미리보기와 편집 → 리더에 적용 → 연결 → 변경 요약과 적용 → 결과 |
| 기기의 책을 앱에서 읽기 | 기기 보관함 → 책 선택 → 앱으로 가져오기 → 서재에서 열기. 지원과 파일 확보를 확인한 후 이어 읽기 제안 |
| 앱과 기기를 오가며 읽기 | 위치 교환 → 해당 책에 이어 읽기 제안 → 사용자 선택 → 이동 또는 유지 |
| 펌웨어 업데이트 | 업데이트 확인 → 호환성 및 주의사항 확인 → 파일 준비 → 연결과 명시적 보내기 → 기기에서 설치 확인 → 재연결 후 버전 확인 |

연결 가능한 경로가 여럿이면 현재 작업에 적합한 경로를 먼저 제안하고, 다른 연결 방법은 필요할 때 펼친다. 사용자의 Apple 기기 Wi-Fi가 바뀌는 직접 연결은 선택 전에 그 영향을 설명하고 명시적으로 선택하게 한다. 인터넷이 필요한 파일 준비는 가능하면 직접 연결 전에 완료한다.

Bluetooth 등록 또는 위치 교환의 성공을 책과 설정을 보낼 수 있다는 의미로 사용하지 않는다. 반대로 Wi-Fi로 가능한 작업을 Bluetooth 등록이 선행되지 않았다는 이유만으로 불필요하게 막지 않는 것을 제안한다. 실제 경로별 조건은 [TRANSFERS.md](TRANSFERS.md)와 펌웨어 계약을 기준으로 명세한다.

macOS의 SD 카드 복사는 보내기 흐름에서 선택할 수 있는 대상이다. 네트워크 연결과 같은 의미의 ‘연결된 리더’로 표현하지 않는다. 복사 성공만으로 기기에서 설치·적용됐다고 표시하지 않는다.

## 작업 상태와 복구

전송 진행은 원래 화면과 공통 진행 표시에서 같은 작업으로 접근한다. 상세 로그를 상시 펼치지 않고, 진행 상황과 사용자가 해야 할 일을 우선한다. 장기 이력 화면이 필요한지는 사용성 검토 후 정한다.

| 상황 | 필요한 행동과 표현 |
| --- | --- |
| 연결 과정 취소 | 선택한 책과 편집 내용을 남기고 출발점으로 돌아간다 |
| 전송 도중 연결 끊김 | 완료 여부를 구분해 표시하고, 확인 또는 재시도를 제공한다 |
| 완료 응답을 받지 못함 | 실패나 성공으로 단정하지 않고 같은 기기에서 결과를 확인한다 |
| 파일은 전달됐지만 펌웨어 설치 대기 | ‘리더에서 설치 확인 필요’와 기기에서 해야 할 행동을 보여 준다 |
| 재연결한 기기가 작업 대상과 다름 | 대상을 확인하기 전 파일이나 설정을 보내지 않는다 |
| 권한 거부 또는 공간 부족 | 그 원인을 해결하는 행동과 작업으로 돌아오는 경로를 제공한다 |

단순 연결이나 책 전송에 반복 확인을 붙이지 않는다. 설정 충돌, 삭제, 펌웨어 설치처럼 결과를 이해해야 하는 행동에 필요한 확인을 둔다. 펌웨어는 앱의 명시적 안내와 기기에서의 설치 확인을 유지하며, 설치 확인을 연결 성공에 묶지 않는다.

## 용어와 선택 부담

| 피할 모호함 | 제안하는 구분 |
| --- | --- |
| 앱과 기기에 모두 사용하는 Reader | ‘앱에서 읽기’와 ‘내 리더’ |
| 앱 첫 화면과 기기 화면을 모두 Home으로 지칭 | 앱은 ‘서재’, 기기는 ‘리더 홈 화면’ |
| 무엇이 바뀌는지 모르는 Sync | ‘읽던 위치 공유’, ‘리더로 보내기’, ‘리더에서 가져오기’ |
| 저장과 기기 적용이 섞인 Apply | ‘앱에 저장됨’, 행동은 ‘리더에 적용’, 결과는 확인된 상태 |
| 동작을 알 수 없는 버튼 반전 | 기기 그림과 ‘이전 쪽 / 다음 쪽’ 결과 |
| 막힌 상태만 알리는 Connect to apply | 하려던 작업 안에서 실행 가능한 연결 행동 |

영문 최종 명칭은 이 의미를 유지해 별도로 정한다. 화면마다 항상 큰 설명문을 붙이기보다 제목, 대상, 미리보기와 동작 결과로 설명한다. 고급 설정과 기술 정보는 관련 상세 화면에서 제공한다.

상위 목적, 편집 대상, 옵션 값을 모두 같은 모양의 버튼으로 표현하지 않는다. 목적지 이동은 내비게이션으로, 대상 선택은 한 곳에서, 값 조정은 그 값에 맞는 컨트롤로 표현한다. 연결되지 않았다는 이유로 모든 화면을 안내 카드로 채우지 않는다.

## 상세 명세와 구현 대응

다음 항목은 [화면과 작업 흐름 명세](PRODUCT_UX_SPEC.md), [IA 구현 설계](IA_FINAL_DESIGN.md), [기기 기능 표](READER_CAPABILITIES.md), [전환 계획](IA_MIGRATION_PLAN.md)에 구체화했다.

1. **화면별 책임:** 서재, 읽기, 내 리더 첫 화면, 기기 보관함, 화면 꾸미기, 읽기 방식, 기기 관리의 진입점과 주 행동.
2. **상태와 과업:** 미등록·미연결·부분 연결·전송 중·실패·설치 대기 상태에서의 화면과 복귀 규칙.
3. **편집 동작:** 즉시 반영과 기기 적용의 구분, 자동 저장, 적용 범위, 연결 후 병합, 미리보기의 정확도 표시.
4. **기기 기능 표:** X3/X4 및 지원 펌웨어별 방향·글자·버튼·화면·파일 작업의 실제 지원 범위.
5. **화면 구성:** iPhone·iPad·Mac에서 같은 IA를 유지하는 배치, 문구, 키보드와 접근성 동작.

이번 범위는 앱의 전체 책 기본 외관, 기기별 Reader Settings 및 카드 내용, 여러 리더 등록과 Same Wi-Fi 동시 연결이다. 작업 화면에서는 한 대를 선택하되 다른 기기의 연결과 작업은 유지한다. 직접 Wi-Fi 연결은 한 대씩 사용한다. 독립적인 카드 제품 경험과 전체 서재 파일의 자동 양방향 동기화는 후속 제품 범위로 남긴다. 읽던 위치 공유와 명시적 책 보내기로 핵심 동선이 완결돼야 한다.

## IA 검토 기준

다음 과업을 설명문에 의존하지 않고 찾고 완료할 수 있는지 프로토타입으로 검증한다.

- 기기 없이 첫 책을 가져와 읽고, 앱 글자 크기를 바꾼다.
- 연결되지 않은 리더에 보낼 책을 선택하고, 선택을 잃지 않은 채 연결과 전송을 마친다.
- 홈과 대기 화면을 편집하면서 현재 대상, 저장 위치, 적용 범위를 구별한다.
- X3 또는 X4에서 가로로 읽을 때 어떤 버튼이 다음 쪽인지 예측한다.
- 다른 곳의 읽던 위치 제안을 받았을 때 현재 위치를 유지할 수 있다.
- 연결이 끊긴 작업을 찾아 결과를 확인하거나 다시 시도한다.
- 펌웨어가 전달된 상태와 실제 설치가 확인된 상태를 구별한다.

명칭과 계층은 실제 과업 검증으로 확인한다. 구현 및 검증 결과는 상세 명세의 완료 기준과 대조하고, 해결한 문제와 남은 실기기 수용 항목을 구분해 보고한다.
