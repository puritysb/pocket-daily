# Pocket Daily 화면과 작업 흐름 명세

작성일: 2026-10-05, 개선 기준 갱신: 2026-10-09. [IA 구현 설계](IA_FINAL_DESIGN.md)와 [UX 개선 기준](IA_UX_REFINEMENT.md)에 상세 결정을, [구현 보고](IA_IMPLEMENTATION_REPORT.md)에 실제 검증 결과를 기록한다. 기능 검증과 사용자 과업의 수용 여부는 구분한다.

[제품 IA](PRODUCT_IA.md)를 화면의 책임, 주 행동, 상태 전이로 구체화한다. 앱 독서와 기기 활용을 동등하게 제공하며, 연결이 필요한 작업은 출발한 맥락을 유지한다. 코드 대응과 개발 순서는 [IA 전환 계획](IA_MIGRATION_PLAN.md)을 따른다.

## 이번 명세의 범위

서재, 앱 읽기, 내 리더, 기기 보관함, 화면 꾸미기, 기기 읽기 방식, 기기 관리, 앱 설정의 책임을 정한다. 첫 구현 단위는 서재에서 선택한 책을 리더로 보내는 전체 흐름이다. 나머지 화면의 배치와 X3/X4 옵션별 값은 [IA 구현 설계](IA_FINAL_DESIGN.md) 및 [기기 기능 표](READER_CAPABILITIES.md)에 확정했다.

기존 제품 원칙과 [전송 계약](TRANSFERS.md), [이어 읽기 계약](READING_PROGRESS.md)은 유지한다. 아래는 설계상 동작과 수용 기준이며, 실제 검증 범위는 구현 보고에서 구별한다. 한국어 문구는 의미 기준이고, 실제 앱의 영문 문구는 같은 범위와 행동을 표현하도록 작성한다.

## 공통 화면 구성

- 공통 제목, 간격, 아이콘 칸, 행동 영역과 카드 규격은 [디자인 시스템](DESIGN_SYSTEM.md)을 따른다. Mac은 창 제목 중복을 없애고 본문 헤더가 상단 공간을 활용한다.
- 주 내비게이션은 서재와 내 리더다. 내 리더 첫 화면에 기기 상태·작업·보관함을 합치며, 별도 Overview와 On Reader 메뉴를 두지 않는다. Reader settings와 기기 옵션 메뉴의 Manage reader는 그 안의 상세 화면이다. 앱 설정은 보조 진입점에 둔다. 읽기는 책을 열어 들어가는 집중 화면이다.
- 화면 상단은 대상과 제목, 본문은 콘텐츠 또는 미리보기, 주 행동은 현재 과업에 맞춰 한 곳에 둔다. 이동 메뉴와 옵션 선택을 같은 모양의 버튼 행으로 반복하지 않는다.
- 앱 설정은 바로 조절할 수 있는 컨트롤을 우선한다. 짧은 설정을 위해 별도 선택 화면을 연속해서 열지 않는다.
- 책 보내기·화면 편집처럼 진행 중인 작업 안의 연결 절차에는 데모 진입을 두지 않는다. 데모는 Device와 일반 연결 화면에서만 연다.
- 연결, 파일 전송, 위치 교환, 적용, 설치 상태는 구분한다. 특정 작업을 할 수 있는지는 지원 기능과 현재 연결을 함께 판단한다.
- 설정과 작업 시트는 이를 연 창에 붙인다. 기기 연결을 이유로 다른 macOS 창이나 데스크탑으로 이동시키지 않는다.
- 좁은 화면에서는 한 열, 넓은 편집 화면에서는 미리보기와 컨트롤을 나란히 배치한다. 값 변경 시 미리보기와 적용 행동을 다시 찾을 필요가 없어야 한다. 좁은 화면의 작은 미리보기는 눌러서 편집을 벗어나지 않고 전체 크기로 확인한다.
- 아이콘만으로 상태나 기능을 구분하지 않는다. 키보드 포커스, 스크린리더 명칭, 큰 글자에서의 줄바꿈을 제공한다. 진행 중 상태는 포커스를 반복 이동시키지 않는다.

## 화면별 책임

| 화면 | 진입점 | 먼저 보여 줄 내용 | 주 행동과 결과 |
| --- | --- | --- | --- |
| 서재 | 첫 실행과 주 내비게이션 | 읽던 책·글, 콘텐츠 목록과 검색 | 콘텐츠 열기. 비어 있으면 책 추가 |
| 앱 읽기 | 서재의 책·글 | 읽던 페이지와 최소한의 조작 | 읽기 계속. 설정 변경은 실제 페이지에 즉시 반영 |
| 내 리더 | 주 내비게이션 | 기기 상태, 확인 시점, 조치할 작업, 기기 보관함 | 연결, Reader settings, 기기 옵션 메뉴. 미연결에도 초안 편집 가능 |
| 기기 보관함 | 내 리더 첫 화면 | 기기 파일, 앱에도 있는지, 마지막 확인 시점 | 파일 선택 후 앱으로 가져오기 또는 명시적인 기기 삭제 |
| 화면 꾸미기 | 내 리더 → Reader settings → Home/Sleep screen | 편집할 홈 또는 대기 화면과 미리보기 | 값 조정 후 해당 화면 변경을 리더에 적용 |
| 읽기 방식 | 내 리더 → Reader settings → Reading preferences | 대상 기기, 책 예시, 현재 방향과 버튼 결과 | 독서 옵션 조정 후 읽기 설정을 리더에 적용 |
| 기기 관리 | 내 리더 → 기기 옵션 → Manage reader 또는 작업의 상세 연결 | 연결 정보와 업데이트 상태 | 필요한 연결·업데이트·문제 해결 수행 |
| 앱 설정 | 보조 진입점 | 앱 외관, 이어 읽기 정책, 권한과 도움말 | 바로 조정. 기기 편집 옵션은 여기 두지 않음 |

서재에서 책을 누르면 앱에서 읽는다. ‘리더로 보내기…’는 책의 행동 메뉴와 선택한 콘텐츠의 도구 막대에서 접근한다. 별도 책 상세 페이지를 반드시 거치게 하지 않는다. 책 추가 취소 시 분류와 스크롤을 유지한다.

앱 읽기 외관은 첫 전환에서는 기존처럼 전체 책의 기본값으로 유지하고 ‘앱에서 읽는 모든 책에 적용’이라는 범위를 표시한다. 책별 외관 예외는 이번 전환에 추가하지 않는다. 뒤로 가면 서재의 이전 위치로 돌아간다.

내 리더는 기기 한 대를 선택한 맥락으로 동작한다. 미연결이어도 화면 편집을 계속할 수 있다. 지원 기능을 모를 때는 모델을 선택한 예시임을 알리고, 연결 시 실제 지원 범위를 다시 확인한다. 여러 기기를 동시에 관리하는 UI는 후속 범위다.

기기 보관함은 마지막 관측과 현재 확인을 구별한다. 연결이 없으면 마지막 목록을 보여 주되 갱신·다운로드·삭제에 필요한 연결을 해당 행동에서 안내한다. 보관함이 아직 없으면 연결 행동을 제공한다. ‘리더에서 삭제’는 앱 서재 사본을 지우지 않는다.

## 편집과 적용

화면 꾸미기와 읽기 방식은 Reader settings 한 화면의 Home screen / Sleep screen / Reading preferences 선택으로 전환한다. 선택기는 편집 영역 안에 두며 적용·되돌리기·미리보기는 해당 범위만 다룬다. 설정을 나갔다 돌아와도 선택한 범위를 유지한다. 조정 결과는 적용 전 미리보기에서 확인하며, Apply를 눌러야 미리보기가 나타나는 구조를 만들지 않는다. 기기 화면 캡처를 다시 도입하지 않고 기존 로컬 렌더러와 책 예시를 활용한다.

| 편집 대상 | 저장과 적용 범위 | 결과 표현 |
| --- | --- | --- |
| 앱 읽기 외관 | 앱에 즉시 저장 및 반영 | 현재 책 페이지에서 바로 확인 |
| 리더 홈 화면 | 홈에 속한 변경만 | 앱에 저장됨 → 적용 중 → 확인된 기기 반영 상태 |
| 리더 대기 화면 | 대기 화면에 속한 변경만 | 홈과 동일한 방식 |
| 리더 읽기 방식 | 글자·여백·방향·버튼 등 독서 변경만 | 기기에 저장됨. 실제 책에서의 표시 여부는 별도 |
| 카드 원본과 공통 내용 | 영향을 받는 화면과 내용 변경을 명시 | 적용 대상과 영향을 먼저 확인 |

기기 편집의 행동 명칭은 ‘리더에 적용’으로 통일한다. 대상 제목과 변경 요약으로 범위를 설명한다. 홈과 대기를 전환해도 각 초안은 보존되며 다른 화면의 변경을 함께 보내지 않는다. 적용할 변경이 없으면 ‘변경 없음’ 상태를 표시하고 같은 요청을 반복 전송하지 않는다.

연결이 필요하면 같은 작업 시트에서 ‘리더 연결’을 제공한다. 연결 성공 후 편집 내용과 기기 값을 병합하고, 지원되지 않는 변경과 충돌을 표시한 뒤 적용할 수 있게 한다. 연결 성공만으로 전송하지 않는다. 실행을 시작할 때 보낸 변경 묶음을 고정하고, 그 이후 편집한 값은 다음 변경으로 남긴다.

카드·날씨·일정은 재사용할 내용으로 관리한다. Home/Sleep에는 원본 요약과 편집 진입만 두며 원본 폼과 여러 적용 버튼을 펼쳐 놓지 않는다. 카드와 날씨·일정은 각각 제목·범위·단일 적용 행동이 있는 전용 편집 화면에서 조절한다. 내용 변경이 홈과 대기에 공통으로 영향을 주면 이를 보여 준다. 닫기 또는 연결 후 복귀해도 부모의 대상·초안·미리보기가 보존된다. 특정 캘린더 선택은 공통 원본의 저장·조회 계약에 따른다.

버튼 설정은 X3/X4별 기기 그림 한 곳에 ‘이전 쪽’과 ‘다음 쪽’을 붙여 결과를 보여 준다. 같은 정보를 별도 대응표와 설명문으로 반복하지 않는다. 회전에 따라 표시도 바뀌어야 한다. 화면 방향과 글의 세로쓰기는 구분한다. 읽기 예시가 실제 기기 페이지와 다를 수 있음을 짧게 알린다.

## 첫 구현 단위인 책 보내기

### 진입과 화면

서재에서 한 권 또는 선택한 여러 권의 ‘리더로 보내기…’를 누르면 현재 창에 작업 시트가 열린다. 첫 배포는 한 권의 진입점부터 연결해도 되지만 작업 모델은 명시적인 책 목록을 받는다. 여러 권 선택 UI는 별도 완료 항목이다.

시트에는 책 제목과 수량, 대상 리더, 현재 단계, 주 행동을 표시한다. 이미 연결된 기기라면 ‘1권 보내기’를 한 번 눌러 실행한다. 미연결이면 같은 위치에 ‘리더 연결’을 보여 주고, 연결 후 ‘1권 보내기’로 바뀐다. 전송을 다시 확인하는 별도 대화상자는 추가하지 않는다.

연결 단계는 이 시트 안에서 전환한다. 사용자가 선택한 책과 돌아갈 화면을 유지하며, 완료 후 Files 화면으로 강제로 이동하지 않는다. 공통 진행 표시에서 같은 작업을 다시 열 수 있어야 한다. macOS에서는 같은 시트에서 SD 카드 대상을 고르고 목적 폴더만 선택한다. 원본 책을 다시 고르게 하지 않으며 SD 복사 결과와 무선 게시 결과를 별도로 보존한다.

최초 대상이 없으면 기기를 찾아 사용자가 선택한 대상을 고정한다. 이미 작업 대상을 정했다면 다른 기기의 응답을 자동으로 채택하지 않는다. 신원을 확인할 수 없는 기기는 기존 호환성 정책 안에서 명시적으로 선택하게 하며, 확인된 동일 기기라고 표시하지 않는다.

### 작업 상태

| 상태 | 표시 | 주 행동 또는 전이 |
| --- | --- | --- |
| 준비 중 | 선택한 책을 준비하는 중 | 준비 완료 후 필요한 연결 또는 보내기 단계. 취소 가능 |
| 연결 필요 | 책 목록과 대상, 연결이 필요한 이유 | 리더 연결 |
| 연결 중 | 현재 단계와 기기에서 필요한 행동 | 취소 또는 문제에 맞는 재시도 |
| 보내기 가능 | 준비된 책과 확인된 대상 | N권 보내기 |
| 다른 작업 대기 | 선택은 유지하고 진행 중인 작업 표시 | 해당 작업 보기. 준비되면 보내기 가능으로 이동 |
| 전송 중 | 현재 책, 전체 중 순서, 진행률 | 중지. 중복 보내기 금지 |
| 결과 확인 중 | 파일 저장 결과를 확인하는 중 | 같은 기기에서 결과 확인. 무조건 재전송하지 않음 |
| 일시 중지 | 완료된 책과 남은 책 | 확인이 필요한 항목을 먼저 확인한 뒤 남은 책 계속 보내기 |
| 일부 완료 또는 실패 | 책별 완료·실패·미전송 상태와 이유 | 해결 가능한 항목만 재시도 |
| 완료 | 저장이 확인된 책과 기기 | 닫기. 필요하면 기기 보관함 보기 |

연결 가능 여부와 작업 상태는 별도로 관리한다. 연결이 끊겼다는 이벤트 하나로 전송 결과를 실패로 바꾸지 않는다. 연결 복구 후 준비한 목록과 기기 신원을 다시 확인하고, 명시적인 보내기 행동을 기다린다. 결과 미확인 상태에서 다른 리더가 연결되어도 같은 시트 안에서 원래 리더의 재연결로 이어진다. 다른 작업 보기는 그 작업을 실제로 제어하는 화면을 연다.

### 선택과 전송의 범위

- 이번 작업은 시작 시 명시적으로 선택한 책만 포함한다. 기존에 준비돼 있던 다른 책이나 펌웨어를 포함하지 않는다.
- 책 ID와 준비된 전송 ID를 연결한다. 파일명이나 ‘방금 큐에 추가된 마지막 항목’으로 대상을 추정하지 않는다.
- 준비한 책 파일은 앱이 읽는 원본과 동일한 바이트를 사용한다. 앱의 읽던 위치 전송은 파일 전송 성공과 별도로 표시한다.
- 실행 중 추가한 책은 현재 작업에 합류하지 않는다. 다시 누른 동일 작업은 새 전송을 만들지 않고 진행 중인 작업을 연다.
- 여러 권은 책별로 완료를 기록한다. 전체가 하나의 원자적 트랜잭션인 것처럼 표현하지 않는다. 중간 실패 후 이미 완료된 책을 다시 보내지 않는다.
- 성공은 기존 원자적 게시 계약이 확인한 저장 결과를 기준으로 한다. 기기에서 책을 열었다거나 읽던 위치까지 맞췄다고 표시하지 않는다.
- 동일 경로에 기존 파일이 있을 때의 교체 동작은 전송 계약에서 확인해 표시한다. 실제로 관측되지 않은 덮어쓰기나 중복 여부를 추정하지 않는다.

### 취소와 복구

연결 단계의 ‘취소’는 작업 시트의 연결 필요 상태로 돌아온다. 시트를 닫는 것은 작업 삭제가 아니다. 원래 서재 상태를 유지하고 진행 표시에서 다시 열 수 있다. 미전송 작업을 버리는 행동은 별도로 제공한다.

전송 중 시트를 닫아도 앱이 실행 가능한 동안에는 전송을 계속한다. ‘중지’는 기존 작업의 취소와 종료 대기를 거친다. 기기에서 이미 저장했을 가능성이 있으면 완료 여부를 확인하기 전 재전송하지 않는다. 준비한 사본 삭제와 기기의 임시 파일 정리는 기존 계약의 대상 확인 및 정리 절차를 따른다.

앱이 종료되거나 백그라운드 실행이 제한되면 연속 전송을 약속하지 않는다. 재실행 시 준비된 항목과 불확실한 게시 상태를 복구하고 자동 전송하지 않는다. 이미 확인된 완료 항목과 아직 확인할 항목을 구별한다.

## 후속 화면의 수용 기준

내 리더에서는 등록 여부와 관계없이 기기 활용 목적지를 찾을 수 있어야 한다. Bluetooth 위치 교환만 가능한 상태에서 책 전송 가능으로 표시하지 않는다. 기기 보관함은 과거 정보와 현재 확인을 구별해야 한다.

꾸미기와 읽기 방식에서는 적용 전 결과를 볼 수 있고, 연결과 화면 이동 후에도 초안이 남아야 한다. Home 적용이 Sleep이나 Reading의 미적용 변경을 전송해서는 안 된다. 폼 입력과 미리보기 작업이 메인 스레드를 오래 막지 않도록 취소 가능한 렌더링과 중복 요청 억제를 유지한다.

펌웨어는 준비·전달·기기 설치 확인·재연결 검증을 구분한다. 연결된 리더의 Update 확인은 다운로드와 보내기를 함께 승인하며, Download update for later는 준비 후 별도의 Send update 확인을 받는다. 두 경로 모두 기기의 설치 확인을 유지한다. 날씨와 일정은 내용을 중심에 두고 제공자 표시는 의무를 확인한 뒤 크기와 위계를 정한다. 기존의 긴 설명문을 줄이더라도 필요한 다음 행동은 화면에 남긴다.
